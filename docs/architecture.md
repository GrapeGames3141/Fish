# Architecture

`src/domain/fishing_session.gd` owns deterministic game rules, explicit state machine, quality-to-distance mapping, and the continuous pull/ease fight. `fish_definition.gd` owns data, including each planned fish’s tension strength, pulse phrase, and fight cadence. `motion_service.gd`, `save_service.gd`, `haptic_service.gd`, and `admob_service.gd` are replaceable platform adapters. `MotionService` samples gravity, acceleration, and gyro once per update, derives linear acceleration, and uses an explicit portrait/right-handed coordinate contract: physical right / `+X` is cock, pull, and hook; physical left / `-X` is snap and ease. It learns a serializable two-cast profile only from that right-then-left sequence and rejects a wrong-handed saved axis. During REELING, signed X pose travel permits only leftward motion to learn/ease toward zero load and only rightward return to build continuous `fight_load`; pitch/YZ-only or rightward motion cannot ease. Directional, gyro-confirmed lower/pull transitions provide hysteretic guidance markers only. `src/ui/main.gd` composes passive Android instructions, motion calibration, sensor-only fight information, desktop-only keyboard simulation, haptic dispatch, and capture mode. `tests/test_runner.gd` calls domain/adapters headlessly.

`HapticService` is an injected-emitter scheduler rather than a timer-only side effect. `start_fight` reserves a short hook-confirmation delay, then `update_fight` can schedule at most one bounded phrase at a time, leaving the fish’s configured quiet gap. Normal species phrases yield to a universal 0.8-second high (65%) warning cadence and a faster universal 0.5-second urgent red (90%) cadence, then reset to normal when tension falls. Terminal cues stop the fight before emitting their distinct result. Turning haptics off clears pending work, so no vibration can leak after a setting change.

AdMob integration is intentionally isolated: the adapter’s native-bottom contract returns a zero Godot reserve, exposes measured native height only for diagnostics, and safely handles absence of the singleton in desktop/headless tests. After UMP consent, `AdMobService` enters `sdk_initializing`, passes an `OnInitializationCompleteListener` to Poing, and requests the banner only from the first current completion callback. Injected initialization and banner-request callables let headless tests prove that early, duplicate, and stale completion paths cannot produce duplicate native views.
