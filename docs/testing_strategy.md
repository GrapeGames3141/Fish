# Testing Strategy

Run deterministic domain tests for state transitions/timeouts, clockwise reel behavior, tension escape, cast-distance mapping, save migration/round trip, learned motion traces, desktop AdMob contract, and project settings. Motion tests prove a stable dwell plus two calibration casts produces a validated profile, wrong order/noise/slow traces fail, faster accepted snaps cast farther, and smaller profile-relative back gestures are active only in the hook-window contract. Source tests reject cast/hook touch copy or hit paths and require an explicit Android guard around keyboard simulation. The AdMob seam asserts no native banner request before SDK completion, exactly one afterward, and duplicate completion callbacks are ignored. Haptic tests inject an emitter and assert all six fish signature/cadence pairs are unique, phrases do not accumulate per frame, the hook confirmation precedes the first species phrase, high/red warnings repeat at universal escalating cadences, normal/high/red tier transitions reset correctly, disabling clears pending work, caught/escaped terminal rhythms differ, and Android amplitude maps/clamps to 1–255. Source tests retain the direct AndroidRuntime vibrator contract: API 33+ uses explicit media VibrationAttributes, API 26–32 uses game/sonification AudioAttributes, min-SDK API 24–25 uses the legacy duration-plus-AudioAttributes overload, and non-Android uses `Input.vibrate_handheld` fallback. Export settings tests assert the arm64-only, compressed-native, signed debug package, Android `VIBRATE` permission, recursive non-runtime exclusions, and retention of runtime AdMob mediation dependencies. Use capture scenarios `ready`, `armed`, `bite`, `reeling`, `caught`, `escaped`, and `synthetic_reserve` to render 720×1280 evidence.

Physical Android validation is a later gate: verify real two-cast calibration, cast/hook recognition and comfort, cast distance feel, vibration timing, lifecycle, UMP, native adaptive banner geometry, touch comfort, and performance on a named device. Desktop success does not validate those properties.

Final Gate 1 evidence includes deterministic domain tests, parser import, signed APK inspection, install evidence, and limited Pixel interaction traces. The final `0.1.4-gate1` arm64 APK is 38,973,335 bytes, SHA-256 `CBCC74703FB5172454A276616AF4DB62720CEAB1FC0415D9C40A8BED2D749061`, versionCode 5 / min SDK 24 / target SDK 36, v2 signed with the existing debug certificate. It is installed on the Pixel 9 Pro with VIBRATE granted. The v2 private save holds a calibrated profile and physical markers recorded casts at `0.79` / `33.4 m` and `1.00` / `40 m`, plus hook-to-reeling transitions. V5 vibrator-manager history attributes bite, hook, and fight cues to `usage: MEDIA` with finished playback rather than `ignored_for_settings`; subjective strength/feel has not been confirmed. The final observed window was launcher while the application PID stayed alive. Therefore foreground visuals, touch comfort, lifecycle, UMP, real banner geometry, performance, and user motion/haptic acceptance remain unvalidated.
