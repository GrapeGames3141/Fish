# Testing Strategy

Run deterministic domain tests for state transitions/timeouts, continuous pull/ease tension and progress, a 10–20 second Bluegill safe rhythm, high-load fast resolution, cast-distance mapping, save migration/round trip, learned motion traces, desktop AdMob contract, and project settings. Motion tests prove a stable dwell plus two calibration casts produces a validated profile, wrong order/noise/slow traces fail, faster accepted snaps cast farther, smaller profile-relative back gestures are active only in the hook-window contract, and fight lower/pull references reject shakes, no-gyro poses, off-axis returns, and repeated markers while exposing a continuous gravity-derived load. Source tests reject cast/hook/reel touch or drag paths and require an explicit Android guard around keyboard simulation. The AdMob seam asserts no native banner request before SDK completion, exactly one afterward, and duplicate completion callbacks are ignored. Haptic tests inject an emitter and assert all six fish signature/cadence pairs are unique, phrases do not accumulate per frame, the hook confirmation precedes the first species phrase, high/red warnings repeat at universal escalating cadences, normal/high/red tier transitions reset correctly, warning amplitude rises while cadence shortens, disabling clears pending work, caught/escaped terminal rhythms differ, and Android amplitude maps/clamps to 1–255. Source tests retain the direct AndroidRuntime vibrator contract: API 33+ uses explicit media VibrationAttributes, API 26–32 uses game/sonification AudioAttributes, min-SDK API 24–25 uses the legacy duration-plus-AudioAttributes overload, and non-Android uses `Input.vibrate_handheld` fallback. Export settings tests assert the arm64-only, compressed-native, signed debug package, Android `VIBRATE` permission, recursive non-runtime exclusions, and retention of runtime AdMob mediation dependencies. Use capture scenarios `ready`, `armed`, `bite`, `reeling`, `caught`, `escaped`, and `synthetic_reserve` to render 720×1280 evidence.

Physical Android validation is a later gate: verify real two-cast calibration, cast/hook recognition and comfort, continuous raised/lowered load comfort, safe-versus-sustained fight timing, vibration timing, lifecycle, UMP, native adaptive banner geometry, touch comfort, and performance on a named device. Desktop success does not validate those properties. The v6 Pixel fight gate did prove lower/pull recognition but landed at 66.42 seconds, outside the target because its exact original-pose return requirement was too strict; the v7 tolerant continuous-load tuning is unexported and has no physical claim yet.

Final Gate 1 evidence includes deterministic domain tests, parser import, signed APK inspection, install evidence, and limited Pixel interaction traces. The signed v7 `0.1.6-gate1` arm64 APK is 38,974,951 bytes, SHA-256 `E0DBDF20E0F1318A1DF556659E5187F1D8E4C6485B52E3B477AD606BF0B56B32`, versionCode 7 / min SDK 24 / target SDK 36, VIBRATE-present and v2-signed with the existing debug certificate. Export stdout reached `[DONE]` with empty stderr; the lingering task console and Gradle daemon were stopped cleanly. Wireless ADB had no mDNS service, so v7 is not installed or physically validated; v6 remains installed. The v2 private save from v5 evidence holds a calibrated profile and physical markers recorded casts at `0.79` / `33.4 m` and `1.00` / `40 m`, plus hook-to-reeling transitions. V5 vibrator-manager history attributes bite, hook, and fight cues to `usage: MEDIA` with finished playback rather than `ignored_for_settings`; subjective strength/feel has not been confirmed. Therefore v7 foreground visuals, touch comfort, lifecycle, UMP, real banner geometry, performance, physical continuous-fight timing, and user motion/haptic acceptance remain unvalidated.
